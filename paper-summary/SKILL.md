# 单篇文献全文总结 Skill

## 核心原则

- **仅基于 Zotero 文献库中该论文的内容**，不编造不存在的信息
- 所有内容必须有原文依据
- 信息缺失时填"未提及"

## 执行流程

### 1. 定位文献

通过 Zotero MCP 检索文献库（**不要直连 SQLite**）。

**优先使用语义搜索**（BAAI/bge-m3 向量嵌入），**若排名不理想则回退到 collection 路径下钻**。

#### 方法 A：语义搜索（首选）

1. 调用 `search_library`，参数：`query`、`semantic: true`、`limit: 200`
2. 搜索返回全部结果，**不要只看 top 10**——专有名词/缩写（如 "REHEARSE-3D"）在语义排序中可能排名极低（实测排第 92/166）
3. 遍历全部结果查找目标论文，或用多个 query 变体（全称、简称、DOI）交叉搜索

#### 方法 B：Collection 路径下钻（语义搜索排名不佳时回退）

1. `get_collections` → 找到目标一级 collection
2. `get_subcollections` → 下钻到目标子 collection
3. `get_collection_items` → 直接命中（通常 4-10 篇，不会遗漏）

#### 定位后

- 调用 `get_item_details` 获取题录信息
- 调用 `get_content`，**必须使用 `mode: "complete"`**（默认 `standard` 仅返回 3K 字符），参数：`itemKey`, `mode: "complete"`, `include: {pdf: true}`, `contentControl: {preserveOriginal: true}`
- 如未找到，提示用户，等用户指示是否从网络搜索

### 2. 类型识别

自动识别文献类型，并告知用户：

| 类型 | 识别依据 |
|------|---------|
| **研究论文** | 提出新方法/算法/模型/理论，有实验验证 |
| **综述论文** | 标题含"survey/review/综述/调研"，内容为领域文献梳理 |
| **数据集论文** | 发布新数据集或基准评测，核心贡献为数据资源 |

识别后告知用户："识别为 XX 类文献"，用户有异议可纠正。

### 3. 内容提取

阅读题录、摘要，读取 PDF 全文，按对应模板提取信息。

### 4. 写入 Markdown 文件

**不走 MCP `write_note`**（Zotero 的 Markdown→HTML→Markdown 来回转换会破坏格式）。直接将 Markdown 写入 `.md` 文件到 Better Notes 同步目录。

#### 文件位置

`/mnt/d/Administrator/Desktop/个人文件/ZoteroNotes/`

#### 文件命名

文件名与正文第一行一致：`论文简称 全文总结.md`（如 `REHEARSE-3D 全文总结.md`）

#### 文件格式

YAML frontmatter + H1标题行 + 生成信息行 + 模板正文：

```markdown
---
parent: '完整论文标题'
zoteroKey: 'Zotero物品KEY'
tags: [AI总结]
model: xx模型
---

# 论文简称 全文总结

> 由 XX模型 于 YYYY-MM-DD 生成

按模板正文...
```

#### 关键规则

- YAML 头后的**第一行必须是H1标题**，格式为 `# 论文简称 全文总结`（Zotero/Better Notes 用此行作笔记标题）
- YAML 中 `tags: [AI总结]` 用于 Zotero 中筛选
- 第三行格式为 `> 由 XX模型 于 YYYY-MM-DD 生成`，写入时填入实际模型名和当天日期
- YAML 中 `model` 字段填入实际使用的模型名
- 正文用标准 Markdown：H1 标题（`#`）、H2 一级小节（`##`）、H3 二级小节（`###`）、`-` 列表、`>` 引用、表格、代码块
- 公式用标准 LaTeX 语法
- 在相应位置插入关键核心图表，采用[图1/表1]格式
- 写入后告知用户：文件已生成，需在 Better Notes 中 **从 md 文件导入笔记** 并勾选 **保持同步**（仅初次需要）

### 5. 按模板输出

#### 模板 A：研究论文（结构化叙述）

```markdown
**本文用[方法]解决了[问题]，核心发现是[关键结果]。**
---

## 1. 引言
- 详细介绍本研究所处的领域，当前关键挑战或现象
- 梳理作者引用的关键文献，总结现有研究的主要观点和不足
- 明确指出本文所针对的"研究缺口"

---

## 2. 方法
- 按照原文逻辑分节介绍所采用的方法、假设、原理等
- 梳理并串联起各个方法之间的联系脉络、数据流
- 对于核心的创新点，在该方法后面标注`[原创]`

---

## 3. 实验与结果
- 总结并说明实验方法、实验条件，对实验数据来源、类型、大小等必要属性进行说明
- 先对实验结果进行客观呈现（标注结果来源`[figure 1]`），然后进行分析
- 说明那些实验结果最有力地证明了该论文的方法、假设、数据等的有效性和可信性

---

## 4. 讨论
- 结果的深度解读
- 主要贡献：对现有技术的验证/扩展/修正，还是提出了新框架/方法/理论
- 研究局限性（数据、方法、适用范围等）与改进方向
- 与我们研究内容的关联（若上下文中未提及我们的研究内容可忽略）

---

## 5. 核心参考文献
- 列出文献综述部分引用的最重要 3-5 篇参考文献，帮助定位学术脉络

## 6. 工程可复现评估
- 是否开源 / 硬件需求 / 复现难度 / 数据可获得性
```

---

#### 模板 B：综述论文（结构化叙述）

```markdown
## 结构化摘要
- 覆盖领域 / 综述方法 / 核心发现 / 主要结论

## 1. 综述范围与方法
- 领域界定与时间跨度
- 分类框架与组织逻辑

## 2. 领域发展脉络
- 奠基性工作与里程碑
- 技术演进路径（按时间或技术代际展开）

## 3. 核心方法分类与对比
- 每类方法：关键思想、代表文献、性能区间

## 4. 领域现状与评估
- 当前技术水平 (SOTA)
- 领域共识
- 尚存争议

## 5. 研究空白与未来方向
- 作者指出的空白
- 结合用户研究方向的空白判断

## 6. 核心参考文献
- 该综述引用的 5+ 篇关键文献列表
```

#### 模板 C：数据集论文（结构化叙述）

```markdown
**数据集名称与规模**：[名称]，[总帧数/点数/场景数]，[天气条件覆盖]

## 数据采集
- 传感器型号与配置
- 采集场景与环境（受控/开放道路/仿真）
- 天气条件的控制方式与参数范围

## 标注方法
- 标注类别与体系
- 标注生成方式（人工/自动/半自动）
- 标注质量指标

## 数据格式与模态
- 文件格式与数据组织
- 各模态传感器数据说明
- 关键元数据（气象参数、标定等）

## 覆盖场景
- 天气类型与强度
- 光照/时间条件
- 场景多样性（目标类型、距离、角度）

## 基准模型与关键结果
- 论文评测的基线方法
- 最重要的 1-3 个实验发现（对你有启发的）

## 开源与获取
- 是否开源 / 获取链接 / 申请流程
- 数据使用许可类型

## 局限
- 已知的数据质量问题或方法局限

## 与本研究关联
- 你能用这份数据做什么
- 数据对你的方法的特殊价值
- 需要注意的适配问题
```

总结完成后，如用户想深入了解论文中的具体方法/模块，将自动进入 `paper-read` 交互式深度问答模式。

## 轻量追踪

如果本轮总结暴露出明显的检索失败、用户纠正或重复请求，可在
`/home/glc/.codex/skill-tracking/usage.jsonl` 追加一条 JSONL 记录。不要为每次正常
执行强制作记录；追踪只用于后续人工复盘。

推荐放入 `quality_signals` 的字段：

| 字段 | 值域 | 说明 |
|---|---|---|
| `search_method` | `semantic` / `collection_fallback` / `direct` | 使用了哪种文献定位方式 |
| `search_rank` | int 或 null | 目标论文在首次语义搜索结果中的排名（未使用语义搜索则为 null） |
| `search_retries` | int | 定位文献总共试了几次（含 query 变体重试和方案回退） |
| `content_mode` | `minimal` / `preview` / `standard` / `complete` | 最终使用的全文提取模式 |

不要写旧的 `skill-evolution/traces/paper-summary/*.yaml`。
