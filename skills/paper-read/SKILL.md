# 论文深度阅读 Skill

## 配置

- `SUBJECTS_DIR`：学科知识目录，默认 `~/.agents/memory/user_knowledge/subjects/`
- `KNOWLEDGE_DIR`：概念级知识目录，默认 `~/.agents/memory/user_knowledge/concepts/`

## 何时触发

以下三种情况触发：

1. **斜杠命令**：用户输入 `/paper-read` 时触发。

2. **paper-summary 后提示**：`paper-summary` 刚执行完时，主动提示用户：
   > "已获取论文概览。需要进入深度阅读模式（/paper-read）针对具体概念或方法进行追问吗？"

3. **不确定时询问**：若上下文暗示用户在针对某篇论文问答，但无法确定是否应触发 Paper Read 模式时，询问用户：
   > "需要我以 Paper Read 模式回答吗？"

论文上下文通过 Zotero 当前活跃条目或对话历史推断。

## 执行流程

### 1. 确认论文上下文

若对话中已有明确论文条目，直接使用。否则从 Zotero 查找（同 `paper-summary` 定位流程：语义搜索优先，collection 下钻回退）。

### 2. 知识边界感知

每轮回答问题前，将用户问题涉及的概念拆解为前置依赖链，然后通过两级知识目录确定用户当前掌握程度。

#### 知识查找流程

```
Step 1 — 将概念映射到所属学科/子主题（如 SVD → linear-algebra → qr-svd）
Step 2 — 查 SUBJECTS_DIR/linear-algebra.yaml，读 qr-svd 的 level
Step 3 — 若找不到学科映射，回退查 KNOWLEDGE_DIR/概念名称.yaml
Step 4 — 若无对应文件，视为 L0
```

#### 掌握程度分级（L0–L3）

| 层级 | 含义 | 判断标准 |
|------|------|---------|
| **L0 · 未知** | 无此概念记录 | 先确认用户了解程度再回答 |
| **L1 · 概念层** | 知道它是什么、干什么用 | 能说出"xx 是用 yy 方法解决 zz 问题" |
| **L2 · 方法层** | 知道具体实现/网络结构/流程 | 能画出模块图、说出关键参数选择 |
| **L3 · 原理层** | 理解底层数学/理论 | 能推导、能解释为什么这样设计 |

#### 学科级元信息

学科知识文件（`subjects/*.yaml`）中包含两个辅助标记：

**广度（课程覆盖范围）**

| 标记 | 含义 |
|------|------|
| C1 | 只接触过部分章节（< 40%） |
| C2 | 核心章节都学过（40–80%） |
| C3 | 覆盖绝大部分内容（> 80%） |

**时效性**

| 后缀 | 含义 |
|------|------|
| (f) | fresh — 常在用/近期复习过 |
| (d) | decay — 有衰减，碰见能捡起来 |
| (r) | rust — 需要重新学 |

学科查表时额外判断：若子主题 level < 所需，但该学科 breadth ≥ C2 且 timeliness 为 (d)，说明是学过但遗忘了——可在提示中加入"你学过这个，有印象吗？"而非直接当作完全未知。

#### 缺口识别与补全

回答每个问题时，先判断：**要给出完整回答，用户需要掌握 X 到哪个层级？**

将"回答所需层级"与"用户当前层级"对比：

| 缺口 | 行为 |
|------|------|
| 无缺口（用户层级 ≥ 所需层级） | 直接回答 |
| 有缺口（用户层级 < 所需层级） | 执行补全流程 |
| 未知（无对应文件，L0） | 先问："你对 X 了解多少？" 分级后按上表处理 |

**补全流程**：

若用户在本会话开始时声明"全程自动补全"，或对话中曾说过"以后这类缺口直接补"，则后续遇到缺口跳过询问，直接补齐并告知"以下内容已自动补全"。否则逐次询问。

1. 若概念映射到已知学科的子主题：
   > "你学过 [子主题名]（[L1/L2]），需要我从这个层级补到回答所需的 [层级] 吗？"
   
   若映射到学科且属于"学过但遗忘"（level < 所需但广度 C2+、时效 (d)）：
   > "你学过 [子主题名] 但有衰减，要我帮你恢复一下再继续吗？"

2. 若不映射到已知学科 → 保持原有询问：
   > "要回答这个问题，需要理解 X 的[实现细节/底层原理]。你目前对 X 的了解在[概念层/方法层]，要我把这之间的内容补上吗？"

3. 用户确认后，先填补缺口（将 X 从当前层级拓展到所需层级），再回答问题。

4. 用户拒绝后，仍给出回答，但注明哪部分理解可能受限。

**注意**：回答本身不降级。无论用户层级高低，始终以完整回答为目标，只是路径不同——直接回答 vs. 先补缺再回答。

#### 知识模型更新

对话中自动推断用户知识变化并更新对应 YAML 文件：

- 用户准确使用了之前不懂的概念 → 晋升对应子主题的 level
- 用户明确说"这部分我懂了" → 晋升 level
- 用户反复追问某概念的细节，且追问中暴露理解困难 → 降级评估
- 若追问表现出逐渐深入，维持或升级
- 首次接触的新领域 → 按对话内容初始化，L1 或 L2

**更新目标**：
- 学科内的子主题 → 更新 `subjects/` 下对应 `.yaml` 中该子主题的 `level`
- 跨学科概念（无法映射到单一学科） → 更新 `concepts/` 下对应 `.yaml`
- 原 `user_knowledge_model.md` 不再使用

### 3. 完整优先，例子辅助

解释任何概念/方法/模块时，**先全貌再局部**：

1. **先说全貌**（必须）：
   - 它包含哪些组成部分
   - 每个部分做什么
   - 输入/输出是什么
   - 在整个系统中的位置

2. **再定位**：用户具体问的是其中哪个部分

3. **然后举例**（可选）：
   - 例子必须标注适用范围："以 X 为例，这只是其中一种情况"
   - 禁止用"就是"来描述局部（"掩码就是对 X 进行衰减" → 错误）
   - 必须用"包括 A、B、C，其中 A 是..."

**例外**：当问题指向单一、确定的事实（如超参数值、数据集名称、公式编号）且不涉及原理解释时，直接回答，无需先展开全貌。

#### 自查清单

回答前检查：
- [ ] 我是否先说了完整包含什么，再说用户问的具体部分？
- [ ] 我用的例子是否说明了"这只是其中一种情况"？
- [ ] 我有没有把局部当成全部来说？

### 4. 来源溯源

对每个技术/方法/思想/模块，标注出处：

| 标签 | 含义 |
|------|------|
| `[原创]` | 本文作者首次提出 |
| `[引入]` | 已有方法，本文首次引入本领域 |
| `[通用]` | 业界通用/广泛使用的方法 |
| `[（xxx,年份）]` | 来自前人某篇论文/特定工作 |
| `[不确定]` | 无法从论文判断来源，诚实标注 |

有时是前人的工作后来成为业界通用/广泛使用的方法，则标注为`[（xxx,年份）通用]`
溯源只需一句话，不展开成段落。

## 笔记记录（手动触发）

用户说"记录一下"、"写到笔记"等时，调用 `note` skill 的**类型 A（论文笔记）**，将对话中涉及的概念写入 `.md` 文件。

具体模板、格式规范和来源标签规则详见 `note` skill。paper-read 本身不再维护独立的笔记模板。

不自动记录。只有用户明确触发时才写笔记。
